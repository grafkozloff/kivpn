# QWEN.md — kivpn

## Обзор проекта

`kivpn` — бесплатный консольный VPN-клиент для Windows 10/11 x64 для частного использования (обход блокировок).
Приложение работает как менеджер конфигураций и оркестратор подключения: хранит и импортирует серверные профили,
проверяет их доступность, выбирает активный сервер и управляет внешним VPN-модулем (xray / sing-box / wireguard-go),
который устанавливает само сетевое соединение. Без внешнего модуля приложение работает в режиме менеджера конфигураций.

**Текущая стадия: каркас Maven-проекта на Spring Boot.** Есть требования, документация, C4-диаграммы и первый код:
`pom.xml` (parent `spring-boot-starter-parent`), точка входа `org.kivpn.Main` (`@SpringBootApplication`)
и консольный цикл как Spring-бины (`org.kivpn.cli.ConsoleAdapter`, `org.kivpn.cli.CommandRouter`),
тесты JUnit 5 + `@SpringBootTest`. SQLite-слой реализован (`org.kivpn.db`, `org.kivpn.model`).
Ещё нет: `run.bat`, парсеров профилей, провайдеров источников, проверки серверов и оркестрации подключения.

Целевой стек: Java 21 (`maven.compiler.release=21`), Maven, **Spring Boot 3.5 (без web)**, SQLite (`org.xerial:sqlite-jdbc`), консольный ввод/вывод.

## Сборка и запуск

### Приложение

- Сборка: `mvn clean package` → исполняемый `target/kivpn.jar` (F6, F7, S4). Проверено: сборка и 11 тестов проходят.
  Исполняемый jar собирает spring-boot-maven-plugin (repackage, зависимости в `BOOT-INF/`, запуск через `JarLauncher`).
- Прямой запуск: `java -jar target/kivpn.jar` — проверено, консольный цикл работает.
- Запуск через `run.bat` из корня проекта (F4, F5): скрипт должен переключать консоль в UTF-8 (`chcp 65001`),
  проверять наличие `java` и `target/kivpn.jar` и запускать JAR (R4, R5, U4). **TODO: `run.bat` ещё не создан.**
- Данные: `data/kivpn.db` создаётся идемпотентно при первом запуске (F8, F9) — SQLite-слой ещё не реализован.
- **JDK 21 обязателен** (`maven.compiler.release=21`). Установлен Oracle JDK 21.0.12.1: `C:\Program Files\Java\jdk-21.0.12.1`;
  `mvn -B clean install` с ним проверен (10 тестов, артефакт в локальном репозитории).
  **Системные переменные не обновлены:** `JAVA_HOME` указывает на JDK 17, `java` в PATH — Java 8,
  поэтому сборку запускать как `set "JAVA_HOME=C:\Program Files\Java\jdk-21.0.12.1" && mvn -B clean package`
  (или обновить системные переменные и проект в IDE).

### Рендеринг диаграмм (проверено)

PlantUML CLI (jar не хранится в репозитории; C4-библиотека подключается по URL, нужна сеть):

```
java -jar plantuml.jar -charset UTF-8 -checkonly diagrams/container.puml diagrams/component.puml
java -jar plantuml.jar -charset UTF-8 -tpng -o diagrams diagrams/container.puml diagrams/component.puml
```

- **Обязательно `-charset UTF-8`**: без него CLI на Windows читает файлы в локальной кодировке и кириллица превращается в mojibake.
  `-checkonly` проходит и при неверной кодировке — проверять именно рендер.
- Имена PNG берутся из идентификаторов `@startuml` (`kivpn-c4-container`, `kivpn-c4-component`).
- В актуальной C4-PlantUML у `System_Ext`/`System` **нет параметра технологии**: сигнатура
  `($alias, $label, $descr, $sprite, ...)`. Технология внешних систем включается в текст описания;
  передача технологии третьим аргументом даёт артефакты `<$...>` в рендере.
  У `Container`, `ContainerDb`, `Component` параметр технологии есть (третий аргумент).

## Соглашения и правила разработки

Язык и интерфейс:
- Java 21, стандартный Maven-проект; зависимости фиксируются в `pom.xml` (минимум `org.xerial:sqlite-jdbc`) (S1–S3).
- Spring Boot используется как каркас DI/конфигурации/упаковки, **без web-стека**: приложение остаётся консольным (F2, F3).
  Баннер отключён (`spring.main.banner-mode=off`), журналы Spring направлены в stderr (`logback-spring.xml`, уровень WARN),
  чтобы stdout принадлежал только консольному интерфейсу. Консольный цикл запускается из `main()` после поднятия контекста,
  поэтому `@SpringBootTest` не блокируется на чтении stdin.
- Только консольный интерфейс (`stdin`/`stdout`), без GUI, установщика, служб и автозапуска (F2, F3, +R4–+R6).
- Сообщения пользователю — на русском, ошибки — в `stderr` и в понятном виде (U2, U3, F14).
- Кодировка консоли UTF-8; в `run.bat` — `chcp 65001` (U4).
- Базовый набор команд: `help`, `add`, `import`, `list`, `check`, `use`, `update`, `connect`, `disconnect`, `status`, `exit`
  плюс экспорт профиля (U7, F42). Секреты и ключи не показываются в списках и не попадают в журналы — только маскированные значения (U8, R10).

База данных:
- Только SQLite, файл `data/kivpn.db` (путь настраивается свойством `kivpn.db.path`); при открытии соединения применять
  `PRAGMA journal_mode=WAL; synchronous=NORMAL; foreign_keys=ON; busy_timeout=5000;` (F10, F11, P1, +R9).
  Реализовано: `SqliteConnectionManager` открывает соединение на операцию (все закрываются try-with-resources),
  `SchemaInitializer` применяет миграции по `PRAGMA user_version` в транзакции; удаление источника не удаляет
  профили (`ON DELETE SET NULL`), удаление профиля каскадно удаляет его проверки.
- Инициализация каталога `data`, файла БД и схемы — идемпотентная; повторный запуск не теряет данные (F9, R3, R11).
- Схема версионируется, изменения — через миграции или совместимое чтение (S8).
- JDBC-ресурсы закрываются при завершении; обновление источников не удаляет пользовательские профили без явной команды (F13, R2, R9).

Сеть и процессы:
- Все сетевые операции — с таймаутами; ошибки сети не роняют приложение (R6, R7, P5).
- Никаких фоновых автоматических процессов: обновление источников и проверки — только по команде пользователя (F24, P6).
- Внешний VPN-модуль запускается как дочерний процесс и обязательно останавливается при отключении, смене профиля и выходе;
  сбой модуля обрабатывается, «осиротевших» процессов не остаётся (F34, F35, R8, R12).
- Источники серверов — отдельные провайдеры (ручной ввод, файл, подписка, VPN Gate, публичные списки), включаемые/отключаемые;
  публичные источники вспомогательные и могут быть недоступны (S6, F20–F23, +R13).
- Поддержка протоколов и внешних ядер расширяемая: минимум `vless`, `ss`, `trojan`; опционально `wireguard`, `amneziawg`, `hysteria2`, `tuic` (F37, S7).
- При активном подключении — весь трафик через туннель, минимизация утечек DNS и IPv6, если модуль/ОС это поддерживают (F38–F40).

Тестирование и документация:
- Код должен быть пригоден для тестирования без реальной сети: парсеры профилей, работа с БД, логика выбора серверов (S10).
- Документация по сборке, запуску и командам поддерживается в `README.md` (S9); архитектурные изменения отражаются в `diagrams/`.
- Проект разрабатывается одним человеком для частного локального использования: предпочтительны простые прагматичные решения
  без командной инфраструктуры (CI-пайплайны, отдельные роли и т.п.) (+R7).

## Ограничения (не нарушать)

- Целевая ОС только Windows 10/11 x64; Java 21; Maven; SQLite (без внешних СУБД).
- Без GUI, установщиков (`.exe`, `.msi`, `jpackage` и т.п.), служб, автозапуска и планировщика.
- Без регистрации, аккаунтов и оплаты внутри приложения; собственного платного VPN-сервиса нет.
- Фактическое VPN-подключение допускается только через внешний исполняемый модуль; путь к нему задаёт пользователь.
- Для создания системного туннеля могут требоваться права администратора — это зависит от внешнего модуля (+R14).
