# Требования к приложению: бесплатный консольный VPN-клиент kivpn для обхода блокировок в России

| Код | Требования | Комментарий |
| --- | --- | --- |
| F | Функциональные (Functionality) | |
| F1 | Приложение называется `kivpn`. | Имя используется в артефактах сборки, скриптах запуска и файлах данных. |
| F2 | Приложение является консольным приложением для Windows. | Графический интерфейс отсутствует. |
| F3 | Пользовательский интерфейс реализуется в консоли через `stdin` и `stdout`. | Приложение работает в интерактивном режиме. |
| F4 | Запуск приложения выполняется вручную через `run.bat`. | Установка, службы, автозапуск и планировщик задач не используются. |
| F5 | `run.bat` запускает исполняемый файл `target/kivpn.jar`. | Запуск выполняется из каталога расположения `run.bat`. |
| F6 | Сборка проекта выполняется через Maven. | Основная команда сборки: `mvn clean package`. |
| F7 | Результатом сборки является исполняемый JAR-файл `target/kivpn.jar`. | Запуск выполняется командой `java -jar target/kivpn.jar`. |
| F8 | Приложение использует локальную базу данных SQLite. | Файл базы данных: `data/kivpn.db`. |
| F9 | При первом запуске приложение создаёт каталог `data`, файл базы данных и схему данных, если они отсутствуют. | Инициализация должна быть идемпотентной. |
| F10 | При открытии соединения с базой данных приложение должно включать режим `WAL`. | Требуется выполнить `PRAGMA journal_mode = WAL;`. |
| F11 | При открытии соединения с базой данных приложение должно задавать параметры надёжности и производительности SQLite. | Рекомендуется выполнить `PRAGMA synchronous = NORMAL;`, `PRAGMA foreign_keys = ON;`, `PRAGMA busy_timeout = 5000;`. |
| F12 | Приложение должно предоставлять пользователю интерактивный ввод команд через консоль. | Допускается использование текстовых команд или меню. |
| F13 | Приложение должно корректно завершать работу по команде выхода. | При завершении должны закрываться JDBC-ресурсы и соединения с базой данных. |
| F14 | Ошибки запуска и выполнения должны выводиться пользователю в консоль. | Ошибки рекомендуется выводить в `stderr`. |
| F15 | Приложение должно управлять списком VPN-серверов или профилей подключения. | Профиль может содержать имя, источник, протокол, адрес, порт, ключи, параметры транспорта и статус активности. |
| F16 | Пользователь должен иметь возможность вручную добавлять, изменять и удалять серверные профили. | Управление выполняется через консольные команды. |
| F17 | Приложение должно поддерживать импорт серверного профиля из текстового представления. | Например, строка вида `vless://...`, `ss://...`, `trojan://...` или другой поддерживаемый формат. |
| F18 | Приложение должно поддерживать импорт серверных профилей из локального файла. | Файл может содержать один профиль или список профилей. |
| F19 | Приложение должно поддерживать импорт серверных профилей из подписки по URL. | Источник подписки добавляется пользователем вручную. |
| F20 | Приложение должно поддерживать несколько источников серверов. | Например, ручной ввод, файл, подписка, публичный список. |
| F21 | Приложение должно позволять включать и отключать отдельные источники серверов. | Источники не должны быть жёстко зашиты как единственный способ получения серверов. |
| F22 | Приложение должно поддерживать опциональный источник публичных серверов через API VPN Gate. | Источник может быть отключён по умолчанию. |
| F23 | Приложение должно поддерживать опциональные публичные списки или подписки. | Такие источники рассматриваются как вспомогательные и не гарантируют постоянную работоспособность. |
| F24 | Пользователь должен иметь возможность обновить источники серверов командой из консоли. | Обновление выполняется вручную, без фоновых автоматических процессов. |
| F25 | Приложение должно выполнять проверку доступности серверов. | Проверка может использовать сетевое соединение, таймауты и протокол-специфичные тесты, если это возможно. |
| F26 | Приложение должно сохранять результаты проверки серверов. | Например, статус, задержка, время последней проверки, ошибка. |
| F27 | Приложение должно показывать список серверов с их статусом. | Пользователь должен видеть имя, источник, протокол, статус и задержку, если она известна. |
| F28 | Пользователь должен иметь возможность выбрать активный сервер вручную. | Выбор выполняется консольной командой. |
| F29 | Приложение должно поддерживать автоматический выбор рабочего сервера по результатам проверки. | Приоритет может отдаваться серверам с успешной проверкой и меньшей задержкой. |
| F30 | Приложение должно поддерживать автоматическое переключение на следующий сервер при недоступности активного. | Поведение может быть реализовано как перебор профилей по заданному порядку. |
| F31 | Приложение должно поддерживать команды подключения и отключения активного VPN-профиля. | Например, `connect`, `disconnect`, `status`. |
| F32 | Приложение может использовать внешний исполняемый VPN-модуль для установки сетевого соединения. | Например, внешний процесс на основе `xray`, `sing-box`, `wireguard-go` или аналогичного компонента. |
| F33 | Приложение должно уметь формировать конфигурацию для внешнего VPN-модуля на основе выбранного профиля. | Конфигурация может создаваться во временном или рабочем каталоге приложения. |
| F34 | Приложение должно запускать внешний VPN-модуль как дочерний процесс при активации профиля. | Запуск внешнего модуля выполняется только по действию пользователя или по выбранному режиму автопереключения. |
| F35 | Приложение должно останавливать внешний VPN-модуль при отключении, выходе из приложения или смене активного профиля. | Недопустимо оставлять неуправляемый фоновый процесс после завершения работы приложения. |
| F36 | Приложение должно работать в режиме менеджера конфигураций даже при отсутствии установленного внешнего VPN-модуля. | В этом режиме доступны хранение, импорт, проверка и выбор профилей, но не само подключение. |
| F37 | Приложение должно поддерживать основные форматы профилей, используемые для обхода блокировок. | Минимально целесообразны: `vless`, `ss`, `trojan`. Дополнительно могут поддерживаться `wireguard`, `amneziawg`, `hysteria2`, `tuic`. |
| F38 | При активном подключении приложение должно направлять пользовательский трафик через активное соединение, если это поддерживается внешним модулем и ОС. | Основной режим — весь трафик через активное VPN-соединение. |
| F39 | Приложение должно минимизировать утечки DNS при активном подключении. | Если внешний модуль или ОС поддерживают принудительный DNS через туннель, приложение должно использовать этот механизм. |
| F40 | Приложение должно обрабатывать IPv6 таким образом, чтобы исключить утечку трафика мимо активного соединения. | Допускается отключение IPv6 для туннеля или его принудительное туннелирование, если это поддерживается. |
| F41 | Приложение не должно требовать регистрации, аккаунта или оплаты внутри самого приложения. | Использование внешних бесплатных источников может иметь собственные ограничения, но приложение не должно встраивать платный доступ. |
| F42 | Приложение должно поддерживать экспорт выбранного профиля в текстовый вид или файл. | Это позволяет использовать профиль во внешних клиентах или резервировать конфигурацию. |
| U | Удобство использования (Usability) | |
| U1 | Консольный интерфейс должен быть пригоден для ручного использования без сложного обучения. | Приложение рассчитано на частное использование. |
| U2 | Сообщения пользователю должны быть понятными. | Основной язык сообщений — русский, если отдельно не предусмотрено иное. |
| U3 | Ошибки должны отображаться в понятном виде. | Пользователь должен понимать причину невозможности запуска или выполнения операции. |
| U4 | Ввод и вывод должны корректно работать в консоли Windows в кодировке UTF-8. | В `run.bat` рекомендуется использовать `chcp 65001`. |
| U5 | Приложение должно предоставлять команду справки. | Например, `help` со списком доступных команд. |
| U6 | Список серверов должен быть читаемым в консоли. | Пользователь должен видеть идентификатор, имя, источник, протокол, статус и задержку. |
| U7 | Основной набор команд должен покрывать типовые сценарии работы. | Например: `help`, `add`, `import`, `list`, `check`, `use`, `update`, `connect`, `disconnect`, `status`, `exit`. |
| U8 | Секреты и ключи не должны отображаться в общем списке серверов без явной команды пользователя. | В списках допускается показывать только идентифицирующую информацию и статус. |
| R | Надёжность (Reliability) | |
| R1 | База данных должна быть устойчива к повреждению при аварийных сбоях. | Обеспечивается использованием SQLite в режиме `WAL`. |
| R2 | Приложение не должно повреждать базу данных при штатном завершении работы. | Требуется корректное закрытие соединений и ресурсов. |
| R3 | Повторный запуск приложения не должен приводить к повторной инициализации базы данных или потере пользовательских данных. | Инициализация схемы должна быть идемпотентной. |
| R4 | Приложение должно устойчиво обрабатывать отсутствие файла `target/kivpn.jar`. | `run.bat` должен завершить работу с понятным сообщением о необходимости сборки. |
| R5 | Приложение должно устойчиво обрабатывать отсутствие доступной `java` в системе. | Пользователь должен получить понятное сообщение об ошибке. |
| R6 | Сетевые операции должны выполняться с таймаутами. | Проверка серверов и обновление источников не должны бесконечно блокировать консоль. |
| R7 | Ошибки сети, недоступность источников и недоступность серверов должны обрабатываться без аварийного завершения приложения. | Пользователь должен видеть причину ошибки. |
| R8 | Сбой внешнего VPN-модуля должен обрабатываться приложением. | Приложение должно показать ошибку и при необходимости перевести профиль в статус недоступного. |
| R9 | Обновление источника серверов не должно удалять пользовательские профили без явной команды. | Если источник обновляется, ранее импортированные профили могут помечаться, но не должны молча удаляться. |
| R10 | Секреты, ключи и токены не должны попадать в журналы, справки и обычные консольные выводы. | Допускается показ только маскированных значений или идентификаторов. |
| R11 | После перезапуска приложение должно восстанавливать сохранённые профили, источники и статусы проверок. | Состояние должно читаться из `data/kivpn.db`. |
| R12 | Приложение не должно оставлять запущенный внешний VPN-модуль после завершения работы. | Дочерние процессы должны корректно останавливаться. |
| P | Производительность (Performance) | |
| P1 | База данных должна работать в режиме `WAL` для повышения скорости чтения и записи. | Режим `WAL` является обязательным. |
| P2 | Операции с базой данных должны выполняться без избыточных задержек для локального однопользовательского режима. | Приложение не рассчитано на высоконагруженную многопользовательскую нагрузку. |
| P3 | Запуск приложения должен выполняться одной командой через `run.bat`. | Ручной переход в каталог проекта не должен быть обязательным. |
| P4 | Запуск приложения и загрузка локальных данных должны выполняться за разумное время. | Интерфейс не должен выглядеть зависшим при старте. |
| P5 | Проверка серверов должна использовать короткие таймауты и не блокировать приложение надолго. | Для больших списков допускается последовательная или пакетная проверка с выводом прогресса. |
| P6 | Потребление ресурсов в режиме менеджера конфигураций должно быть низким. | Приложение не должно выполнять постоянные фоновые сетевые запросы без команды пользователя. |
| S | Поддерживаемость (Supportability) | |
| S1 | Проект должен быть стандартным Maven-проектом. | Структура исходников, ресурсов и сборки должна соответствовать стандартной схеме Maven. |
| S2 | Версия языка и компилятора — Java 21. | В `pom.xml` требуется указать `maven.compiler.release` со значением `21`. |
| S3 | Зависимости проекта должны быть зафиксированы в `pom.xml`. | Как минимум используется зависимость `org.xerial:sqlite-jdbc`. |
| S4 | Сборка должна быть воспроизводимой командой `mvn clean package`. | После сборки должен создаваться `target/kivpn.jar`. |
| S5 | Локальные данные приложения должны быть переносимы через файл базы данных. | Для частного использования достаточно хранить и копировать файл `data/kivpn.db`. |
| S6 | Источники серверов должны реализовываться как отдельные модули или провайдеры. | Например: ручной ввод, файл, подписка, VPN Gate, публичный список. |
| S7 | Поддержка протоколов и внешних VPN-модулей должна быть расширяемой. | Добавление нового формата профиля или внешнего ядра не должно требовать полной переработки приложения. |
| S8 | Формат хранения профилей и источников должен быть версионируемым. | При изменении схемы базы данных должны предусматриваться миграции или совместимое чтение старых данных. |
| S9 | Проект должен содержать понятную документацию по сборке, запуску и командам. | Достаточно `README.md` или отдельного файла документации. |
| S10 | Код должен быть пригоден для тестирования. | Желательна возможность тестировать парсеры профилей, работу с базой данных и логику выбора серверов без реального сети. |
| +R | Ограничения (Restrictions) | |
| +R1 | Целевая операционная система: Windows 10/11 x64. | Приложение разрабатывается только для Windows. |
| +R2 | Язык разработки: Java 21. | Использование другой версии Java не требуется. |
| +R3 | Сборка: Maven. | Использование других систем сборки не требуется. |
| +R4 | Графический интерфейс не используется. | Только консольный интерфейс. |
| +R5 | Установщик не требуется. | Форматы `.exe`, `.msi`, `jpackage`, WiX, Inno Setup не используются. |
| +R6 | Автозапуск, службы и задачи планировщика не используются. | Только ручной запуск. |
| +R7 | Приложение предназначено только для частного локального использования. | Многопользовательский режим не требуется. |
| +R8 | Сетевой доступ требуется для обновления источников серверов, проверки доступности серверов и установки VPN-соединений. | Приложение перестаёт быть полностью офлайн-утилитой. |
| +R9 | База данных — только SQLite. | Внешний сервер базы данных не используется. |
| +R10 | Основные артефакты проекта: `run.bat`, `target/kivpn.jar`, `data/kivpn.db`. | Файл базы данных и служебные файлы SQLite создаются в каталоге `data`. |
| +R11 | Для фактического VPN-подключения допускается использование внешнего исполняемого модуля. | Само приложение может выполнять роль менеджера конфигураций и оркестратора подключения. |
| +R12 | Приложение не содержит собственный платный VPN-сервис. | Серверы берутся из пользовательских, бесплатных, публичных или самостоятельных источников. |
| +R13 | Публичные бесплатные источники серверов считаются вспомогательными и не гарантируют постоянную работоспособность. | Приложение должно корректно работать даже при недоступности таких источников. |
| +R14 | Для создания системного сетевого адаптера или туннеля может требоваться запуск с правами администратора. | Это зависит от выбранного внешнего VPN-модуля и способа настройки сети в Windows. |
| +R15 | Внешний VPN-модуль может поставляться отдельно или указываться пользователем. | Приложение может хранить путь к исполняемому файлу внешнего модуля и параметры его запуска. |
